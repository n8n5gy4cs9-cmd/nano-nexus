Build NanoNexus your way

Everything happens on your Apple Silicon Mac. You get a macOS app and a Windows installer, each with one model or a whole set of models bundled in. This works for machines with no internet, and you can also use your assistants from your phone over Wi-Fi.

Status legend: Available now works today with the scripts in this repo · Planned · Mxx the target workflow, available when that milestone in tasks.md is done. Commands stay the same.

Overview

📦 Basic build

The app plus one default model (MiniCPM5 1B Opus-Fable5 V2, ~1.1 GB). Works offline on first launch.

🧰 Custom build

Pick any set of models (catalog, Hugging Face, or your own .gguf files) in the App Builder, then click Build.

💾 Model packs

Add models to an already-installed NanoNexus from a USB stick. No rebuild and no internet needed.

📱 LAN Share

One switch starts a local server on port 9889. Scan a QR code and chat from your phone.

1 · One-time setup on the Mac Available now

  1. Developer tools. Install the Xcode Command Line Tools and Homebrew, then the build tools: 
    xcode-select --install
brew install cmake git
curl --proto '=https' --tlsv1.2 -sSf https://sh.rustup.rs | sh     # Rust (stable ≥ 1.90)
brew install node@22 && corepack enable                           # Node 22 + pnpm
  2. Check everything. 
    scripts/doctor.sh
    Fix every ✖ line. Yellow ! lines are advice.
  3. Create a stable signing identity (recommended). Without it, macOS asks again for Desktop and Documents access after every rebuild.
    Keychain Access → Certificate Assistant → Create a Certificate… → Name: NanoNexus Local Signing, Identity Type: Self-Signed Root, Certificate Type: Code Signing. Then: 
    echo 'export NEXUS_SIGN_IDENTITY="NanoNexus Local Signing"' >> ~/.zshrc && source ~/.zshrc
  4. Build the AI runtime: pinned llama.cpp b11552, Metal, arm64, static. It takes a few minutes. 
    scripts/setup-runtime.sh
  5. Download and verify the default model (~1.1 GB, SHA-256 checked, revision pinned): 
    node scripts/fetch-model.mjs
node scripts/fetch-model.mjs --verify
Where things goEverything heavy lives in vendor/ (git-ignored): vendor/runtime/ for llama-server builds and vendor/models/<id>/ for GGUF files with their lock.json. Nothing large is ever committed.

2 · Basic build: macOS Planned · M12 🍎

The basic build ships exactly one model, the default from bundles/basic.json.

scripts/build-app.sh --profile basic

What it does: checks the toolchain → re-verifies the model and runtime against their locks → stages the files → builds the app → re-hashes everything inside the built .app → signs it with your identity → zips it.

OutputWhere
Apptarget/release/bundle/macos/NanoNexus.app
Zip + checksumsdist/basic/NanoNexus-<version>-basic-macos-arm64.zip, SHA256SUMS.txt

Drag NanoNexus.app to /Applications. It finds its runtime and models wherever it lives. To run it on another Mac, copy the zip and run xattr -dr com.apple.quarantine NanoNexus.app there once (or notarize it, M16).

3 · Windows, built on your Mac Planned · M13 🪟 output

You never need a Windows build machine. The Mac cross-compiles the app (cargo-xwin), packages it with NSIS, and uses the official llama.cpp Windows binaries of the same pinned version, verified by SHA-256.

One-time Windows toolchain

rustup target add x86_64-pc-windows-msvc aarch64-pc-windows-msvc
cargo install --locked cargo-xwin
brew install nsis llvm
echo 'export PATH="$(brew --prefix llvm)/bin:$PATH"; export XWIN_CACHE_DIR=~/.cache/xwin' >> ~/.zshrc && source ~/.zshrc
scripts/doctor.sh --windows
node scripts/fetch-runtime-windows.mjs --arch x64      # Vulkan GPU + CPU fallback (add --cpu-only for the smallest)
node scripts/fetch-runtime-windows.mjs --arch arm64    # Windows on ARM (and VM testing on the Mac)

Build

scripts/build-windows.sh --profile basic --arch x64                    # installer (default for small payloads)
scripts/build-windows.sh --profile basic --arch x64 --format portable  # unzip-and-run, no install
scripts/build-windows.sh --profile basic --arch arm64                  # for Windows on ARM
FormatBest forWhat you copy to the PCInternet on the PC?
InstallerNormal PCs, payload ≤ 1.8 GBNanoNexus-…-windows-x64-setup.exeNo on Windows 11. Windows 10 may need WebView2 once
Portable ZIPNo admin rights, USB useUnzip the folder, run nano-nexus.exe. Data stays in .\data\No (Windows 11)
Offline kitBig multi-model bundles, studio PCsFolder: setup.exe + models-extra\ + WebView2 offline installer + INSTALL.txtNever
Why three formats?NSIS installers can't be much bigger than 2 GB. When the models add up to more than 1.8 GB, the builder automatically switches to the offline kit (or portable ZIP), so any number of models works.
Testing without a PCIn a Windows 11 ARM VM on your Mac (UTM or Parallels), the arm64 build runs natively and the x64 build runs under Windows' x64 emulation (CPU only, slower, fine for smoke tests). Do final GPU and performance checks on the real PC.

4 · Choose which models are bundled Planned · M12

The easy way: App Builder

node scripts/app-builder.mjs

Your browser opens a private page on 127.0.0.1 (protected by a one-time token):

  1. Tick the models. Sizes and a RAM-fit hint are shown. Add any Hugging Face GGUF (repo + quant) or a .gguf on your disk.
  2. Pick the default model, the one that loads first.
  3. Pick targets: macOS, Windows x64, Windows arm64, plus the Windows format (Auto is recommended).
  4. Save the profile (stored in bundles/local/<name>.json) and click Build. Logs stream live. At the end you get the artifacts, their SHA-256s, and Reveal-in-Finder buttons.

The scriptable way: a profile file

Copy the example and edit it. Each model is a catalog id, a Hugging Face repo, or a local file:

cp bundles/studio.example.json bundles/local/studio.json
{
  "schema": 1,
  "name": "studio",
  "models": [
    "minicpm5-1b-fable5-v2-q8",
    "minicpm5-2b-q4",
    { "repo": "Qwen/Qwen2.5-Coder-1.5B-Instruct-GGUF", "quant": "Q8_0", "as": "coder-1.5b" },
    { "local": "~/Models/my-finetune.Q4_K_M.gguf", "as": "my-finetune" }
  ],
  "default": "minicpm5-1b-fable5-v2-q8",
  "targets": ["windows-x64", "macos-arm64"],
  "windows": { "format": "kit", "webview": "offlineInstaller", "runtime": "vulkan" }
}
node scripts/fetch-model.mjs --profile studio          # available now: downloads + verifies all models
node scripts/app-builder.mjs --profile studio --target all --yes   # headless build (M12/M13)

Catalog ids are listed in catalog/models.json. You can also fetch single models now:

node scripts/fetch-model.mjs --id qwen3.5-4b-q4
node scripts/fetch-model.mjs --repo owner/Some-Model-GGUF --quant Q4_K_M --as some-model
node scripts/fetch-model.mjs --local ~/Models/x.gguf --as my-x
node scripts/fetch-model.mjs --list

5 · Recipe: an offline studio PC (Windows, no internet) Planned · M13

  1. On the Mac, open the App Builder, tick the models you want on the studio PC, choose target Windows x64 with format Offline kit, save the profile as studio, and click Build.
  2. Copy the folder dist/studio/NanoNexus-…-studio-windows-x64-kit/ to a USB drive (exFAT works for large files on both Mac and Windows).
  3. On the PC, open the folder on the USB drive and run setup.exe. If you see "Windows protected your PC", click More info → Run anyway (the build is unsigned, which is fine for personal use). The installer copies models-extra\ next to the app.
  4. First launch: NanoNexus verifies every extra model by SHA-256 (with a progress bar) and lists them under Models → Bundled. Pick the active model there.
  5. Optional: turn on 📡 Share to use the studio PC's assistants from other devices on the studio network (section 7).
No internet is ever neededThe kit includes the WebView2 offline installer, the Windows llama.cpp runtime, and all models. Updates work the same way: build a new kit, or send just new models as a model pack.

6 · Add models later, without rebuilding Planned · M12

A model pack is a folder with pack.json plus GGUF files. It works for macOS and Windows installs alike.

Make a pack

node scripts/make-model-pack.mjs --id gemma-4-e4b-q4 --id qwen3.5-4b-q4 --out /Volumes/USB
# or in the app: Models → select models → Export model pack…

Install a pack (offline)

  1. Plug in the USB drive. In NanoNexus open Models → Import model pack… and choose the NanoNexus-ModelPack-… folder.
  2. Choose Copy into NanoNexus (recommended) or Use from this folder (saves disk, but the drive must stay connected).
  3. Every file is SHA-256-verified, and tampered or corrupted files are rejected. The models then appear under Installed.

You can also add a whole folder of GGUFs as a watched extra model folder: Settings → Models → Extra folders (for example, a NAS share).

7 · Use it from your phone (LAN Share) Available now

  1. In the NanoNexus title bar, click 📡 Share and flip the switch ON. It listens on port 9889 by default.
  2. The popover shows the address (for example http://192.168.1.20:9889 or http://nanonexus.local:9889) and a QR code:
    Scan with the phone camera
    or open the address and type the 6-digit PIN.
    Codes expire after 5 minutes.
  3. On the phone, name the device (for example "My iPhone") and tap Pair. Chat, switch assistants, browse history, and read reports. The mobile layout has a bottom tab bar, and desktop browsers get the full layout.
  4. Optional: Add to Home Screen for an app-like icon. (Over plain HTTP the phone still works; the offline shell needs HTTPS.)
  5. Settings → Sharing holds everything else: the port, which network to listen on, the Bonjour name, optional HTTPS, what remote devices may do (default: chat + read granted folders; file changes stay on the computer), allowed assistants, session length, and paired devices (rename or revoke).
Good to knowThe phone can chat, switch assistants, browse history, and read reports. Scanning folders, the editor, Rename Forge, and applying changes stay on the computer. If an assistant on the phone needs a folder you have not allowed, the permission prompt appears on the computer, labelled with the phone's name. Revoking a device in Settings → Sharing ends its session immediately.
First start promptsmacOS may ask "Allow incoming network connections?". Click Allow. Windows Firewall asks which networks to allow: tick Private networks only. Sharing is off by default and every device must pair. The AI engine itself is never exposed, only NanoNexus's own protected API.

8 · Verify integrity Available now for models

node scripts/fetch-model.mjs --verify                  # re-hash every downloaded model against its lock
shasum -a 256 -c dist/basic/SHA256SUMS.txt             # check built artifacts (M12+)
node scripts/verify-payload.mjs path/to/NanoNexus.app  # re-hash everything inside a built app (M12+)

In the app: Models → Verify bundled models re-hashes the models inside the installed app.

9 · Troubleshooting

macOS keeps asking for Desktop/Documents access after each rebuild

The app was ad-hoc signed, so its identity changes on every build. Set up the signing identity from step 1.3 and rebuild.

"Windows protected your PC" (SmartScreen)

Click More info → Run anyway. Personal builds are unsigned. Windows code signing from the Mac is optional (M16).

Windows build fails or the installer is too big

NSIS has a ~2 GB limit. Use --format kit or --format portable (Auto picks one for you). Also run scripts/doctor.sh --windows: makensis, clang-cl, and lld-link must be on PATH.

The app opens on Windows 10 but shows a blank window

WebView2 is missing. Use an offline kit (it includes the WebView2 offline installer) or install WebView2 once.

Slow on the studio PC / "CPU" shown in the runtime panel

The Vulkan GPU backend couldn't load, usually because the GPU drivers are old. Update the graphics drivers. NanoNexus falls back to CPU automatically. Smaller models (1B Q4) are much faster on CPU.

Port 9889 already in use

NanoNexus offers the next free port. You can also change it in Settings → Sharing. To see what uses it: lsof -iTCP:9889 -sTCP:LISTEN (Mac) or netstat -ano | findstr 9889 (Windows).

The phone can't open the address

Make sure both devices are on the same Wi-Fi (not a guest network), that sharing is ON, and that you allowed the firewall prompt. Some routers block device-to-device traffic ("AP/client isolation"). Turn that off or use another network. Try the IP address instead of nanonexus.local.

iPhone: "Local Network" access or the .local name does not work

On iOS and macOS 15+, apps that use the local network need permission. If nanonexus.local does not open, use the IP address shown in the Share popover. On the Mac, check System Settings → Privacy & Security → Local Network → NanoNexus.

The browser warns about the certificate (HTTPS)

HTTPS uses a certificate NanoNexus made for itself, so browsers warn once. Compare the fingerprint in Settings → Sharing with the one the browser shows, then continue. If you do not need HTTPS, leave it off.

The phone says "Session ended"

The device was revoked on the computer, its session expired (30 days by default), or sharing was turned off and on with a new data folder. Pair again with a new QR code or PIN.

Too many wrong codes

After 5 wrong PINs in a minute an address is blocked for 10 minutes and NanoNexus shows a notification. Use the QR code instead, or wait.

Model download fails with 401/403

The repo is gated or private. Accept its license on Hugging Face, create a read token, and run export HF_TOKEN=hf_… before fetching.

"Not enough disk space"

Building copies models into the app, so you need about 2× the total model size free plus 5 GB. scripts/doctor.sh shows free space.

A model repeats itself or rambles

The MiniCPM5 models need min_p = 0 (catalog presets set this). For other models, use the catalog's sampling preset or lower the temperature in the assistant settings.
