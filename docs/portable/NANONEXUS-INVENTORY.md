## API preservation rules

Keep existing command names and serialized shapes unless a separately documented migration adds optional fields. Generated bindings are regenerated by the owning generator only; do not hand-edit them. New portable storage services belong behind existing src/lib/api.ts Transport facade, and desktop-only diagnostics must never enter the LAN command allow-list. Feature-level invoke calls remain prohibited.

Existing model rows contain absolute paths. Never reinterpret an arbitrary old absolute path as a trusted portable path. Portable migration requires explicit source selection, digest checks and registration; do not silently scan the host profile. Persist portable asset paths as root-relative references and resolve/canonicalize before use. Legacy installed mode continues using its current paths.

## Current limitations to carry forward visibly

The old task tracker still contains unverified model/hardware/platform exit tasks. This inventory does not mark them complete. Current in-flight owner changes in AboutSection, service/app.rs, generated bindings and UI-DESIGN are outside this conversion commit scope. Optional M16 features are not promoted to working features by this inventory. Reference external model links are adapted to USB import; browser localStorage/simulated imports are not an alternate persistence implementation.
